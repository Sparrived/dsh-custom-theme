# dsh-custom-theme v0.5.0 — 2026-10-10

The interface's two most recognizably DeepSeek surfaces become yours to change: a new **Custom
branding** card replaces the sidebar's wordmark and whale, the mark and the wording beside the welcome
headline, and hands you three stylesheet boxes plus stable hooks for everything it does not name. The
same build fixes what a wallpaper did to the window bar: with one set, the popovers that bar opens —
the background-jobs list among them — were painted underneath the conversation.

**本次更新**：新增「自定义品牌」卡片（侧边栏字标与鲸鱼图标、欢迎页标识与文案、三处自定义 CSS，边输入边生效、清空即还原官方外观）；并修复设置壁纸后**后台任务下拉框被正文压住**的问题——顶部栏不再被绘制成独立的层叠上下文。

## Added

- **自定义品牌卡片**（设置 → 主题与背景）：侧边栏的字标文字与鲸鱼图标地址、欢迎标题旁的标识、欢迎标题与预览徽标的文案。所有字段**边输入边生效**，清空即回到官方外观。
- **三个 CSS 输入框**（侧边栏品牌区 / 欢迎标题区 / 徽标）接管行内没有命名的部分；你写的样式表会被**逐字**注入成该功能自己的 `<style>`，不做任何改写。
- **六个稳定钩子**：`[data-dct-brand]`、`[data-dct-hero]`、`[data-dct-hero-badge]`，以及插件绘制的标识上的 `[data-dct-brand-mark]`、`[data-dct-brand-name]`、`[data-dct-hero-mark]`——卡片里列了它们。它们靠 shell 类名的作者后缀定位，所以 shell 重建、类名重新哈希之后你的规则依然命中；想隐藏某处，写 `display: none` 即可。

## Changed

- **整窗壁纸不再单独铺到顶部栏。** 顶部栏是透明的，它背后就是会话列——同一张图、同样的强度与模糊；此前那里会再画一份（也会成为模糊窗口里唯一清晰的一张）。只设整窗壁纸的用户看到的顶部栏与之前一致，只是不再被 isolate。附带的一个变化：这种情况下该区的 `panelOpacity` 不再单独作用于顶部栏，因为这一版的顶部栏在整窗场景里不再被绘制。
- **只给顶部栏单独选图的用户**：图片仍按你设的强度显示，但**不再带该区的模糊**（元素的背景层没有 filter）。这是这次修复唯一可见的取舍。

## Fixed

- **后台任务下拉框不再被正文压住。** 每个绘制区的图片都画在 `z-index: -1` 的 `::before` 层上，而负索引的层只有当元素自身是层叠上下文时才乖乖待在内容之下——所以绘制时会往每个区的宿主上写 `isolation: isolate`。顶部栏的宿主正是 shell 自己的会话头部 `<header>`，而 shell 把头部按钮**和它们打开的弹层**都渲染在里面；这些弹层没有 portal，靠 `z-index: 100` 逃到根层叠上下文才浮在正文之上。被 isolate 之后它们被困住，会话正文（`.Dc7zOa_body`，在 header 之后绘制）便盖住了面板——正文的字直接压着下拉框。现在顶部栏的图片改画在元素自身的 background 上，这不需要任何层叠上下文：背景天然在内容之下。强度变成「面板底色的一层水洗 + 图片」，因为背景层自身没有 alpha；底色仍由该元素自己的 `background-color` 提供。
- **凡是从这条栏打开的弹层都受影响，后台任务只是最显眼的一个。** 修复覆盖全部，不是给这一个列表做的特判。

## Upgrade notes

- 升级后**重启一次 DSH**：客户端插件在启动时加载，桌面端重载窗口也一样。
- 在设置页的**插件更新**卡片里「检查更新 → 升级」即可拿到这一版（它从 npm 装好，重启后生效）；或按你平时的方式把 profile 依赖升到 `0.5.0`。
- **不需要重新配置**：主题、背景、文案与品牌设置原样保留。品牌设置存在 `dsh-custom-theme.branding`，把字段全部清空会把这一条从存储里删掉。

## Verification

- `npm test` — 243 tests, passing.
- `npm run check:client` — `lib/client.js` 与 `src/client/` 一致。
- `npm run test:effects` — 6/6 steps, passing；不需要 DSH、不需要 token。
- `npm run test:popover` — PASS：在真实 Chromium 里按 shell 自己的值复刻现场，按修复前的声明跑正文赢、按这一版的声明跑弹层赢；不需要 DSH、不需要 token。
- `npm run test:working` — 8/10 steps，against a throwaway `dsh web` instance serving this release's own packed tarball. 两个失败都需要「一个带回合的会话」，而一次性实例里一个都没有（`no session row to open`，以及随之而来的 `the shipped rows disappeared`）；**同一个实例、同一份套件跑已发布的 0.4.6 也是 8/10，失败的是同两步**，所以这是环境而不是回归。
- `npm run test:browser` — 38/39 steps，同一实例。唯一失败 `a global image paints every zone and is visible in them`（`composer layer image was none`）在**已发布的 0.4.6 上同样复现**：headless `dsh web` 没有会话时 composer 区不落地，0.4.4 的说明里记过同一现象。两张 fixture 图片（`test-gradient.png`、`test-stripes.png`）按 0.4.4 的做法手工放进了一次性实例的背景目录，否则该套件读图的那几步全部无从谈起。
  - 对照还给出两个本次改动的独立证据：0.4.6 上 `a surface the shell throws away is painted again` **失败**而本版通过（旧版把整窗壁纸铺到顶部栏并给它层叠上下文，本版不铺）；`the plugin injected one style tag per concern` 的计数从 5 变 6，多出来的是品牌功能自己的样式表，断言已跟着更新。
- By hand: 本次没有在窗口里逐项点过；界面侧的断言由上面两套实机套件覆盖（含本次新增的窗口栏平铺契约）。
