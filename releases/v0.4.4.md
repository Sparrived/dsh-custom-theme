# dsh-custom-theme v0.4.4 — 2026-10-07

The tray icon can finally talk: left-click it and a themed menu opens with your unread and recent
sessions, double-click it and the app comes to the front, right-click it and the official menu is
exactly where it was. Nothing is installed, patched on disk or launched differently for this — the
plugin patches the running app in memory at every start, and undoes it the moment you switch the
feature off.

**本次更新**：托盘图标左键弹出会话菜单（未读 / 最近 / 更多，可新建会话、打开、退出），双击唤起主窗口，右键仍是官方菜单；补丁只存在于运行中的内存里，设置页一个开关即可开启或即时撤销。

## Added

- **左键点托盘图标，弹出会话菜单。** 未读会话在最上面（标记 `●`），下面是最近会话，**更多 ›** 展开更早的一批
  （上限 3 / 4 / 12）；运行中的会话带 `◉` 标记。菜单底部是 **新建会话**、**打开 DeepSeek Harness**、**退出**，与
  Windows 原生托盘菜单同一套交互：`Esc` 关闭，方向键与 Home/End 在条目间移动，点击别处立即关闭。菜单随内容自适应
  高度，宽 320、最高到当前显示器的可用工作区，深浅色与字号跟随你正在用的主题。
- **双击托盘图标打开主窗口**；**右键仍然是官方原生菜单**，一个字都没有改。
- **设置里一个开关：主题与背景 → 桌面托盘（运行时补丁）。** 打开后每次桌面端启动都会自动接管托盘，关掉则立刻在
  内存里撤销：还原官方 tooltip 与右键菜单对象、还原被替换的托盘方法、断开 IPC、销毁菜单窗口，下一次启动不再注入。
  卡片会如实显示状态：正在读取状态 / 已在运行的桌面端上生效 / 已开启，等待注入 / 已关闭，以及失败原因。**默认关闭**，
  需要你自己打开。
- **在 Web 页面里这张卡片会说明原因**：`dsh web` 或浏览器里没有原生托盘可接管，卡片显示「仅在 DSH 桌面端可用」并
  把开关置灰，而不是假装能开。

## Changed

- **补丁只活在内存里。** 它不改安装目录、不改 `app.asar`、不注入启动参数、不要求管理员权限、不在应用目录留下任何文件；
  桌面端一退出，补丁随之消失，下一次启动重新施加。关掉开关就是立即卸载，不需要重启、不需要还原任何备份。
- **会话数据是现问现取的。** 菜单每次打开时，插件从官方会话 store 读一次当前状态（未读、最近、运行中、工作区名），
  不抓 DOM、不读私有数据库、不让菜单窗口连接 Host，因此不存在过期快照。
- **菜单窗口是一个独立的本地文档**：独立非持久 session、独立 preload，`sandbox` 与 `contextIsolation` 打开、
  `nodeIntegration` 关闭，拒绝权限请求、禁止导航与新窗口，IPC 只接受属于该文档的调用。

## Upgrade notes

Nothing to do beyond restarting the app once: **the tray is off until you switch it on**, and the half
that applies it lives in the Host process, which only reads the plugin at startup.

- **升级后请重启一次 DSH 桌面端**，否则设置里的托盘卡片拿不到注入结果（Host 侧仍是旧代码），托盘也不会被接管。
- **打开开关会在本机回环地址上开一个约一秒的调试端口**（127.0.0.1 的 9229–9239 之一），注入完成立即关闭；不接受这个
  窗口期就保持开关关闭——托盘会完全维持官方行为。
- 托盘菜单里的日期与标题都来自你的会话，长度、控制字符与颜色在进入菜单前会重新校验；菜单里的会话在被点击时会再确认
  一次是否仍在列表里，已经消失的会话不会被打开。
- 退出按钮走的是应用自己的退出路径，与官方菜单一致。

## Verification

- `npm test` — 218 tests, passing.
- `npm run check:client` — the linked browser bundle is in step with its sources.
- `npm run test:effects` — 6/6 steps, passing; needs no DSH and no token.
- `npm run test:tray-ui` — the menu document in a real Chromium: text safety, light/dark, keyboard, more/back,
  actions, errors and the content-sized layout.
- `npm run test:working` — 10/10 steps, passing, against a throwaway `dsh web` instance serving this
  release's own packed tarball.
- `npm run test:browser` — 38/39 steps. The single failure (*the composer zone carries the global
  picture*) reproduces **identically on the published 0.4.3 artifact** in the same instance, so it is an
  artifact of a headless `dsh web` run rather than a regression from this release, whose changes do not
  touch the appearance or background code. The two fixture images that suite expects in the background
  directory were placed by hand.
- By hand, in DSH Desktop: with the switch on, the app was restarted, and the patch was applied by the
  Host itself with nothing else running — the settings route answered
  `{"enabled":true,"desktop":true,"active":true,"trays":1}`, and inside the main process the patch
  reported one live tray, one click handler, one double-click handler and five IPC channels. A real
  left-click then opened the menu from the installed plugin at 321×373 with the live session list, a
  second click closed it, double-click brought the app forward, the native right-click menu was
  unchanged, and switching the feature off restored the official tray and destroyed the menu window.
