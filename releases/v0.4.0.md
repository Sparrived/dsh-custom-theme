# dsh-custom-theme v0.4.0 — 2026-10-06

The streaming text fade is back. 0.3.1's fade broke the transcript by rewriting the live reply
into spans of its own, and 0.3.2 removed the feature instead of repairing it; this release paints
the same fade with `CSS.highlights`, so the newest characters still settle from the writing ink to
the text colour while nothing about the message's DOM is touched.

**本次更新**：流式渐显回来了——这次用 `CSS.highlights` 绘制，逐字墨迹照常，但不再改动 React 持有的任何节点，因此 0.3.1 的崩溃不会重现。

## Added

- **流式渐显 (streaming text fade) is back** in Appearance settings, with both controls: fade
  duration 150–1500 ms (default 520) and writing ink 5–100% (default 30%, 100% turns the fade off).
  A value stored by 0.3.0/0.3.1 is read again, so upgrading restores the look you had.
- The ink follows the characters just written: each new chunk starts at the writing ink and ramps
  to the text colour over the chosen duration, and the previous chunk is released as soon as the
  next one arrives.

## Changed

- The 0.3.2 promise still holds: the plugin never adds, splits, moves or removes a node inside
  content the shell renders. The fade was rebuilt to work inside that rule rather than around it.
- `::highlight()` paints the characters it covers in one colour, so the newest characters inside a
  link or a bold fragment settle from the surrounding prose colour instead of their own.

## Fixed

- A reply can stream in with the fade on and the transcript stays intact. In 0.3.1 the fade made
  React's commit throw `NotFoundError` out of `conversation.chat.node`; the shell's slot boundary
  then dropped the whole assistant body, leaving a process header with nothing under it, and the
  same message failed again on every later render. The ink holds `Range` objects, which React never
  sees, so there is nothing left for its commit to trip over.

## Upgrade notes

Nothing: upgrade, restart the app, and the fade is on again at 30% ink. If you had the Appearance
page open in 0.3.2, the two controls are back where they were. No setting has to be revisited.

## Verification

- `npm test` — 83 tests, passing. Four cover the ink: the range it claims, its alpha, that the node
  it paints over keeps the same object and parent with no new siblings, and that it is withdrawn
  when the writing ink is 100% or the plugin is disposed. One asserts, on the source, that the
  browser half may not name `createTextNode`, `splitText`, `replaceChild`, `removeChild`,
  `insertBefore` or `innerHTML` at all.
- `npm run test:effects` — 6/6 steps, passing; needs no DSH and no token.
- `npm run test:working` / `npm run test:browser` — not run: they need a live DSH window and a
  `DCT_TOKEN` from the user, and this release was cut without one.
- By hand: the technique was checked in headless Edge on a page that registers the same
  `CSS.highlights` entry over a `Range` at four alphas. The four lines rendered at 100%, 60%, 30%
  and 5% as expected, and rewriting a `nodeValue` the way React's commit does — the exact operation
  the 0.3.1 spans could not survive — left all four ranges registered and threw nothing.

## 中文摘要

- **流式渐显回来了**：外观设置里两个控件都在——渐显时长（150–1500 ms，默认 520）与落笔墨量（5–100%，默认 30%，100% 即关闭）；0.3.0/0.3.1 存过的值会被重新读取。
- **改成了用 `CSS.highlights` 绘制**：用 `Range` 圈住刚写入的字符，由 `::highlight()` 规则把透明度从墨量升到实色；不新建、不拆分、不移动、不删除任何节点。
- **修好了 0.3.1 的崩溃，而不是把功能删掉**：React 的提交再也碰不到插件的痕迹，回复不会变成"只有过程标题的空壳"。
- **升级**：更新后重启应用即可，渐显默认开启（30% 墨量），无需任何额外设置。
- **验证**：`npm test` 83 项通过、`test:effects` 6/6 通过；两个需要真实 DSH 窗口的套件本次未运行；另外用无头 Edge 单独验证了高亮技术本身。
