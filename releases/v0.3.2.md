# dsh-custom-theme v0.3.2 — 2026-10-06

0.3.1 could leave an assistant reply on screen as its process header with nothing underneath. The
reply was never lost — it was stored, and reloading did not help, because the shell was throwing
the body away while rendering. This release removes the cause.

**本次更新**：修复 0.3.1 中回复正文被吞掉的问题——消息只剩「已完成，用时 N 秒」表头、下面一片空白；文字其实一直都在会话数据里，是插件在流式渲染时改写了 React 管理的节点，导致整条正文被丢弃。同时移除引发该问题的「流式渐显」及其两个外观设置。

## Changed

- **流式渐显 (streaming fade) is gone**, together with its two Appearance controls, 流式渐显时长
  and 落笔墨量. It rewrote the live reply into its own text spans as the answer streamed in, which
  is what broke rendering. A duration or ink value saved by 0.3.0/0.3.1 is ignored, and nothing
  else reads it.
- **思考内容展开 (reasoning auto-expand)** keeps every mode and looks exactly the same. Its
  synthetic click on a disclosure row is now scheduled a tick later, so it can never run in the
  middle of a React commit.

## Fixed

- **A reply whose header appeared with no body.** With 0.3.1 loaded, an assistant message with a
  long, markdown-heavy answer could render as its process header and action bar with the whole
  body missing — and it stayed missing across reloads and across the rest of the conversation. The
  fade had rewritten the reply into its own spans while React still held the original text nodes,
  so React's next render called `removeChild` on a node that was no longer its child and threw
  `NotFoundError: Failed to execute 'removeChild' on 'Node'` inside the `conversation.chat.node`
  slot; the shell's slot boundary then dropped the message body. The plugin no longer adds,
  splits, moves or removes any node inside content the shell renders.

## Upgrade notes

- Upgrade and restart. Nothing to reconfigure: the removed controls leave no setting behind, and
  思考内容展开 keeps whichever mode was already chosen.
- A session that was hit by this needs no repair — its text was never lost. It comes back on
  reload once the new version is in place.

## Verification

- `npm test` — 81 tests, passing. Includes a new assertion that the browser half never calls
  `createTextNode`, `splitText`, `replaceChild`, `removeChild`, `insertBefore`, `replaceWith`,
  `insertAdjacentHTML`, `insertAdjacentElement`, `insertAdjacentText`, `innerHTML`, `outerHTML` or
  `document.write`.
- `npm run test:effects` — 6/6 steps, passing; needs no DSH and no token.
- `npm run test:working` / `npm run test:browser` — **not run**: they need a live DSH window and a
  token, and they do not drive the transcript's streamed rendering, which is the path this fix
  changes.
- By hand: the failure was diagnosed in the reporter's own app from its DevTools console —
  `NotFoundError: Failed to execute 'removeChild' on 'Node'` reported against
  `conversation.chat.node`, while the persisted session held the full text, and it disappeared as
  soon as the plugin was disabled and the app restarted.

## 中文摘要

- **修复正文被吞掉**：0.3.1 下，长而富格式的回复可能只剩表头、正文全空，刷新也无效。原因是「流式渐显」在流式期间把正文改写成自己的文本节点，React 提交时 `removeChild` 抛 `NotFoundError`，shell 的 slot 边界于是丢掉整条消息正文。
- **移除流式渐显**及「流式渐显时长 / 落笔墨量」两个设置；旧版本存过的值会被直接忽略。
- **思考内容展开**保留全部模式、外观不变，只是合成点击延后一个 macrotask，不会插进 React 的提交过程。
- **升级后重启即可**，无需重新配置；受影响的会话文字一直都在数据里，装上新版重新加载就会显示。
- 验证：`npm test` 81 项全过（新增"永不改写 shell 渲染的节点"断言）、`npm run test:effects` 6/6；两个需要真实窗口的套件本次未运行（它们不覆盖流式正文渲染这条路径）。
